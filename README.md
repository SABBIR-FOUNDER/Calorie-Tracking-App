# Calorie Tracker

**Calorie Tracker** is a lightweight, beautifully structured Flutter application for recording a single day's meals and tracking progress toward a daily calorie goal. It is designed as a readable, portfolio-friendly Flutter project with Material Design 3, deterministic business logic, and no backend.

> **Privacy by design:** The entire food list stays in process memory. Entries do not leave the device, and they disappear if the application process restarts.

## Highlights

- **Daily dashboard:** Today's date, consumed calories, 2,000 kcal goal, and remaining calories.
- **Daily progress:** Responsive linear progress indicator capped at 100%, with an explicit over-goal message and negative remainder.
- **Fast food logging:** A keyboard-friendly bottom sheet with name and calorie amount fields.
- **Reliable validation:** Rejects missing names, blank-only names, empty or invalid values, zero, negative, and non-finite calories. Names are trimmed.
- **Reliable deletion:** A unique session ID on every entry supports deletion of exactly one item, even if items are identical; a SnackBar offers Undo.
- **Automatic calculation:** Totals, remaining calories, and progress refresh immediately after changes.
- **Simple day reset:** The list resets when the app resumes on a new local calendar day or performs its next date-aware action.
- **Responsive Material 3 UI:** A spacious emerald-and-off-white dashboard, empty state, adaptive summary cards, and accessible controls.
- **No database, network, analytics, account, or state-management dependency.**

## Getting started

### Prerequisites

- Latest compatible **Flutter stable** SDK and Dart SDK (from Flutter)
- Android Studio / VS Code with Flutter and Dart extensions
- For Android builds: Android SDK and Java 17
- For iOS builds (macOS only): Xcode and CocoaPods

Check your setup:

```bash
flutter doctor -v
```

### Install and launch

1. Extract `calorie_tracker_flutter.zip` and open the `calorie_tracker` folder in an IDE.
2. From that folder run:

```bash
flutter pub get
flutter run
```

If Flutter reports a platform migration difference for your SDK version, regenerate tool-managed platform scaffolding **without replacing the `lib/` or `test/` files**:

```bash
flutter create --platforms=android,ios,web --project-name calorie_tracker .
flutter pub get
```

This is not normally required, but Flutter templates and Android Gradle versions can change over time.

The Android Gradle launch scripts in this archive use an installed Gradle if available, otherwise bootstrap the version declared in `android/gradle/wrapper/gradle-wrapper.properties` over HTTPS. This replaces the usual Gradle wrapper JAR, which is not included in the source archive. The first Android build requires network access to resolve Gradle and Android build dependencies if they are not already cached.

### Verify locally

```bash
dart format .
flutter analyze
flutter test
flutter build apk --debug
```

Generated debug APK: `build/app/outputs/flutter-apk/app-debug.apk` after a successful Android build. An APK is **not** included in the ZIP.

`pubspec.lock` is generated by `flutter pub get`. This ZIP does not include a pre-resolved lockfile because the Flutter/Dart SDK and package registry were not available in the packaging environment; see `VERIFICATION.md`.

## Calorie calculation

```dart
totalCalories = foods.fold(0.0, (sum, food) => sum + food.calories);
remainingCalories = 2000.0 - totalCalories;
progress = (totalCalories / 2000.0).clamp(0.0, 1.0);
```

For example, eating 2,300 kcal produces **-300 kcal remaining** and displays **300 kcal over goal**. The progress bar is visually capped at 100% and never misrepresents over-goal intake as remaining calories.

## Memory-only behavior

No food entries persist to local disk, device databases, cloud storage, or APIs. The list is empty on a fresh app process. If the app is suspended across midnight, it clears its in-memory list on resume; adding or removing food also checks the date first. A running screen does not schedule a midnight timer, by design.
